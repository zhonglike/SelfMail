# 架构说明

## 一图流

```
外部邮件服务器 (Gmail/QQ/…)          客户端 (Thunderbird/Outlook/手机)
        │ TCP 25                            │ 993 IMAP / 465 SMTP / 443 Web
        ▼                                   ▼
┌─────────────────────────────────────────────────────────────┐
│                      SelfMail (单进程)                       │
│                                                             │
│  smtp_server   25/465/587   ──收──►  store.deliver          │
│       │            └─外域─► store.enqueue ──► outbound 线程   │
│       │                                        │ DNS(MX/中继)│
│       └─ DKIM 签名（出站统一在入队前完成）        ▼            │
│  imap_server  993/143   ┌──────────────────────┐            │
│  pop3_server  995/110   │  store.py (SQLite)    │            │
│  webserver    443       │  users/aliases/       │            │
│        │                │  folders/messages/    │            │
│        └──► /api/send ──►│  queue/logs           │            │
│  webui (液态玻璃)         └──────────────────────┘            │
│                                    磁盘: data/mail/**/*.eml  │
└─────────────────────────────────────────────────────────────┘
```

## 关键决策与理由

### 为什么是「线程每连接」而不是 asyncio
SelfMail 目标规模是 10-50 人的家庭/小团队，同时连接数几十个。线程模型在 CPython 下每连接约 8MB 栈，几十连接毫无压力，换来的是：
- IMAP IDLE 可以直接 `Event.wait` + 阻塞读，不用 asyncio 复杂的两路等待
- STARTTLS 用 `ssl.wrap_socket` 中途升级，零兼容性坑（asyncio 的 `starttls` 需要重接协议栈）
- 全部协议代码可用同步心智模型书写和调试

### 存储模型：SQLite 元数据 + 磁盘 .eml
- SQLite 存 users/aliases/folders/messages/queue/logs —— 单文件备份、事务一致
- 每封邮件一个 `.eml` 文件按 `data/mail/<user>/f<folder_id>/<uid>.eml` 落盘 —— IMAP 取信、备份、迁移、反垃圾扫描都直接读文件
- 全局一把 `threading.RLock` 串行化写入：该规模下吞吐远超需要，正确性优先

### 邮件流水线
1. **入站**（25 端口）：EHLO → 收件人过滤（本域/别名展开 `resolve_rcpt`）→ DATA 收集（去点填充 + 大小上限）→ 补 `Received:` → `parse_message` 抽摘要 → `deliver`（配额检查 + 通知 IMAP IDLE）
2. **出站**：本地收件人直接投递；外域经 DKIM 签名后 `enqueue`。出站线程（可被 `wakeup` 事件即时唤醒）按 MX 直投或 smarthost 中继，失败指数退避 15m→1h→4h→…→6 次后生成退信（DSN）放回发件人收件箱
3. **Web 发信**：复用与 SMTP 相同的 `_finalize`/DKIM 路径，保证 Webmail 发出的信与客户端发出的信同一质量

### IMAP 兼容性要点
- ENVELOPE/BODYSTRUCTURE 自实现（含 multipart 递归、中文头 RFC2047 解码）
- 非 ASCII 用 modified UTF-7 编码（文件夹名 `测试` ↔ `&XfJT0ZAB-`）
- 字面量(literal)读取按 RFC 3501 语法支持 `{n}` 与 `{n+}`（LITERAL+）
- FETCH 支持 `BODY[]<start.count>` 分片，大附件可断点续读

|---|---|---|
| `config.py` | 配置加载/默认值/域名集合 | ~130 |

| `auth.py` | scrypt 散列 + 失败封禁限流 | ~70 |
